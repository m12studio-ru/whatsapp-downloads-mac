WhatsApp для Mac складывает всё подряд прямо в `~/Downloads`, и отключить это в
настройках нельзя. Эта утилита выделяет ему отдельную папку — как у Telegram Desktop.

Всё, что сохраняет WhatsApp, через пару секунд оказывается в `~/Downloads/WhatsApp`.
Остальное содержимое `~/Downloads` не трогается.

## Установка перетаскиванием

Файл лежит на [странице последнего релиза](https://github.com/m12studio-ru/whatsapp-downloads-mac/releases/latest).

Скачайте `WhatsApp Downloads.dmg`, откройте его и перетащите **WhatsApp Downloads** в
*Программы*. Затем запустите приложение **из папки «Программы»**, а не из самого образа —
оно само установится в фоне.

Приложение не подписано сертификатом разработчика Apple, поэтому при первом запуске
macOS покажет *«файл повреждён»* или *«не удалось проверить»*. Есть два пути:

- щёлкнуть по приложению правой кнопкой и выбрать **Открыть**; если в окне есть только
  *Готово* / *В корзину*, зайдите в *Системные настройки → Конфиденциальность и
  безопасность* и нажмите **Всё равно открыть**; либо
- один раз снять карантин:

```sh
xattr -dr com.apple.quarantine "/Applications/WhatsApp Downloads.app"
```

Если раньше вы ставили версию из командной строки, запуск приложения заменит её фоновый
агент на новый, указывающий на `/Applications/WhatsApp Downloads.app`.

Приложение подписано на вашем Mac, а не Apple. Поэтому каждая новая сборка выглядит
для macOS как другое приложение, и после замены оно снова попросит доступ к
«Загрузкам».

Чтобы собрать образ самому, нужны Xcode Command Line Tools — набор инструментов
разработчика от Apple (`xcode-select --install`). Дальше:

```sh
./build.sh
```

## Установка из командной строки

```sh
git clone https://github.com/m12studio-ru/whatsapp-downloads-mac.git
cd whatsapp-downloads-mac
./install.sh
```

Затем macOS спросит у **WhatsAppDownloads** доступ к папке «Загрузки» — нажмите
**Разрешить**. Если окно проскочило мимо, доступ можно включить вручную:
*Системные настройки → Конфиденциальность и безопасность → Файлы и папки*.

Проверка: положите в `~/Downloads` файл с именем `WhatsApp test.jpg`.

## Удаление

```sh
./uninstall.sh
```

Файлы остаются на месте — удаляется только сама утилита.

## Что устанавливается

| Путь | Что это |
| --- | --- |
| `~/.local/bin/whatsapp-downloads.sh` | сам «перекладчик», небольшой скрипт на zsh |
| `~/Applications/WhatsAppDownloads.app` | крошечная обёртка, которая запускает скрипт |
| `~/Library/LaunchAgents/WhatsAppDownloads.plist` | будит его, когда `~/Downloads` меняется |

Вариант с перетаскиванием ставит только `/Applications/WhatsApp Downloads.app` и тот же
`~/Library/LaunchAgents/WhatsAppDownloads.plist`. `./uninstall.sh` убирает фоновый
агент и всё, что он установил в домашней папке; на удаление `/Applications/WhatsApp Downloads.app` могут
понадобиться права администратора — если не вышло, скрипт об этом скажет.

Зачем нужна обёртка-приложение? macOS выдаёт доступ к папкам отдельно каждому
приложению. Голый шелл-скрипт, запущенный через launchd, видит пустую папку
«Загрузки» и молча ничего не делает — поэтому скрипт живёт внутри приложения,
которому и выдаётся разрешение.

В списке *Системные настройки → Основные → Объекты входа → Разрешить в фоновом
режиме* он виден как **WhatsAppDownloads**, там же его можно выключить.

## Как он себя ведёт

- Переносит файлы, имя которых начинается с `WhatsApp ` — именно так их называет приложение.
- Ничего не перезаписывает: при совпадении имени получится `WhatsApp Image ... (1).jpeg`.
- Не трогает файлы `.crdownload`, `.part` и `.download`, пока браузер не докачает их.
- Папки и все остальные файлы оставляет как есть.

## Настройка

Поправьте три переменные в начале `whatsapp-downloads.sh` или задайте `WA_SRC`,
`WA_DST` и `WA_PREFIX`. Если указать в `WA_SRC` папку за пределами `~/Downloads`,
macOS запросит доступ уже к ней.

## Тесты

```sh
./test.sh
```

Занимает примерно 90 секунд и проверяет настоящий фоновый сценарий — launchd,
приложение и разрешения, — а не просто дёргает скрипт напрямую. Создаёт только
файлы со словом `cctest` в имени и потом удаляет их.
